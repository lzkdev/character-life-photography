# 人物档案与长期连续性

## 一次定义，版本化使用

每个人物使用独立 profile。人物根目录由用户指定或读取项目配置的 profile_root；首次缺档案／参考时按 [首次初始化](initialization.md) 共同建立，不要求用户先手写 JSON。不要写回只读来源。参考本包 `profiles/example-adult/`，但只借用结构，不复制人物内容。

人物目录保留 profile.json、references 与历史版本；拍摄组按 [保存位置与归档](output-storage.md) 存在独立资料库目录。已有目录结构可沿用，不为统一结构擅自移动原始资料。每组先组织方案；仅在 save_records=true 时为每张保存一份 JSON，不创建配套 MD。路径按声明的基准解析，不假设所有设备都有同一绝对路径。

| 档案部分 | 内容 | 变化原则 |
|---|---|---|
| identity | ID、名字、成人／年龄信息、出生日期或固定设定年龄 | 不自动推断毕业、婚姻或职业进展；缺失值留空 |
| canon | 脸部关系、结构化骨相与骨架、皮肤、头发、体型、辨识点、固定饰品与精简身份块 | 用户要求改 Canon 时新建版本，保留旧版 |
| variable_appearance | 可选发型、妆容、衣服；是否允许遮挡饰品等 | 在允许范围内据生活场景变化，同事件内保持连续 |
| life | 性格、职业、居住基点、日常活动、说不准的地方 | 已有事实与拟定情节分开；不自动添加履历 |
| references | 图片路径、用途、版本、SHA-256 与 active 状态 | 只选择与此次时期一致的参考；成图不能自行成为身份母图 |
| style_preferences | 默认摄影风格与可选预设参数 | 可按本次用户要求切换，不改身份 |
| provenance | 事实来源、快照日期、待解决冲突 | 来源缺失或冲突时不包装成定论 |

新人物初始化按 [正面定妆模板](../types/identity-reference.md) 写 canon.structure（face_shape、eyes、brows、nose、lips、body_frame）；面部骨相与肩颈、身形分开。旧档案缺少该块仍可读取，不自动推测或迁移。结构块、face/body 摘要和 identity_prompt 保持一致，拟定或未知内容按来源标注。

身份块只保留真正用于识别的特征。体重、三围等只有人物本身已定义、且对一致性有用时保留；不要求每个人都填。不要把女性、21 岁、白皙皮肤、细腰或固定饰品做成所有人物的必填值。

年龄策略明确为 fixed、birth_date 或 unspecified。fixed 是角色固定年龄；birth_date 根据故事日期计算年龄，但不能据此编造人生变化。未知出生日期不要反推一个生日。

## 默认地点与天气

`life.home_base` 是未指定地点的新日常拍摄默认入口，至少能解析到城市／区域。用户明确指定或设定中仍有效的外出位置优先；不要把设备位置当成人物位置。首次定义长期人物档案时一并定义生活位置，未确定时保留 null 并在需要当地环境时询问。

没有指定日期和天气时，读取该地点的当前当地时间并查询当前天气，不能等用户再次要求。查询结果与来源用于本次方案；开启记录时再写入 JSON，不把“当前天气”写入长期人物 Canon。每个人物使用各自档案，不套用示例城市。

## 参考图的优先级

1. 用户本次明确指定的身份参考与版本。
2. 档案内当前有效的 primary_identity 参考；可辅以同版本的侧脸或全身图。
3. 近期通过 QC 的相关图，作为服装、动作或场景延续参考，不覆盖主脸。
4. 摄影风格图，只借用机位、光线与质感。明确其 role，避免把参考中的另一个人当成身份。

选择参考后实际查看图片，校验文件存在及指纹。文件被替换而档案 hash 未更新时，不再把它当作同一锚点。无脸图不适合单独锁脸；侧脸遮挡图不适合证明正面五官一致。

只有文字的人物定义可以用于首次设计。先生成用户要求的角色设计图；用户选定后再将选中图设为主身份参考并建立可延续的 Canon。不要宣称第一张未经选择的图已是永久母图。

## 每次生图固定什么

本次核对 profile ID、version、文件 hash、选用图片 hash。开启记录时把它们与事件、风格和结果保存到同一个 JSON；关闭时不创建逐图资料。已有历史记录仍保留其原身份版本。

同一个生活事件内，先对照前图的衣服结构、道具数量、空间朝向、发型、天气和时间。换装、移动和光线变化需要本次情节解释。下次生图可以是新事件，无须永久重复一套衣服或每次延续同一个动作。

长期输出的变化主要来自生活：活动阶段、地点、季节、姿态与摄影表达。人设变化来自用户或明确的角色更新；不要让模型为了追求新鲜感自行改脸、染发、加痣、减重或改变种族特征。

## 漂移时如何处理

先区分身份、物理情境与摄影表达。逆光使肤色亮一些不必判为换人；痣移到另一边、脸型变尖或发长跨事件无解释地变化，需要指出。按实际偏差窄幅调整，不反复追加整段强调词。

新模型、不同参考组合与强风格化都可能改变身份表现。比较参考与实际成图，不用相同 seed、文件尺寸、prompt 文本相同或模型自评分代替视觉证据。不要编造身份相似度百分数。
