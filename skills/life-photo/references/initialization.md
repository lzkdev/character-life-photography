# 首次初始化：共同建立可以继续使用的人物

目标是把用户的想法变成选定的人设、主身份图和可持久读取的资料库。没有图片是正常起点，不是必须让用户自行解决的阻塞条件。

## 先利用已有资料

先按 [多人物选择](character-selection.md) 查用户指定档案、当前项目配置中的 `profile_root`、资料库索引和已有对话。用户明确创建新人物时进入独立初始化；给了不匹配的名字时不能沿用其他人物。未指定身份且只有一个明确的当前人物时可沿用；多个且指代不明才询问。完整档案直接使用，缺什么补什么，不重做已完成的选择。用户手动修订和明确选中的版本优先；缺图时先定位原图，找不到再协作恢复或重建。

用户提供参考图时实际查看，区分身份、体型、服装、场景和摄影风格用途。只有背影、严重遮挡或无法看清脸时说明可用范围。记录可见外观；名字、年龄、国籍、职业、性格和住处来自用户或明确的创作方案，不由图像推断成事实。

## 一起定义，避免整张问卷

先用已有信息整理一份简短人设草案，每轮只问 1–3 个真正影响设计的事项。用户只有模糊方向时给 2–3 个简短方向供选择；已有明确方向时直接细化，不强制走选项。让用户用自然语言回答，由 Codex 写入 JSON。

人设覆盖以下几组信息，缺失的可先标待定：

- **是谁**：称呼、虚构人物或用户提供的真人身份、年龄策略、生活或职业背景。
- **长什么样**：按 [骨相与骨架表](../types/identity-reference.md#先把结构说清楚) 明确脸型、眼型、眉形、鼻形、唇形及可见肩颈／身体比例，记录 canon.structure；再补肤色、发型发色、少量辨识特征；固定项与可变项分开。不要套用示例人物，也不要求三围、精确体重或必须有痣／饰品。
- **怎样生活**：性格、常住城市／区域、日常活动和兴趣。首次日常拍摄前应有可用生活位置；未确定时保留空值，不以设备位置代替。实际拍摄时根据地点解析时区。
- **怎样拍与表达**：默认摄影风格、穿搭倾向、与镜头的互动偏好（安静观察、同伴在场、自然回应），用户明确的画面边界，以及需要贴文时的语气／语言。将长期互动偏好写入 style_preferences.notes；本次具体触发和回应写入逐图 interaction，均可在后续拍摄覆盖。
- **保存哪些资料**：在确定保存位置时询问一次是否保留 JSON 拍摄记录；已明确偏好直接采用，未选时默认只保存图片和一份贴文。按 [保存设置](output-storage.md) 记住选择，不自动再输出 JSON 的 MD 副本。
- **存在哪里**：已有项目就提出该项目内具体目录；没有普通项目时请用户选一次长期资料库位置，不默认保存到本次会话目录。配置见 [保存位置与归档](output-storage.md)。

把来源分成用户已给、从既有资料读取、Codex 拟定、尚未确定；proposed 留在来源记录，不能因写入文件就变成已确认事实。先保存 `status: draft` 的 profile。使用既有 Schema，未知值按其允许形式留空；不要为补齐字段臆造履历。

给用户展示精简、可修改的草案。尚未选定的核心外观方向应先取得用户意见再生成候选。用户已经明确授权“按这个设定生成参考图”或“你来定并直接生成”时，不再重复索要同一许可。

## 分轮问答循环

资料不够详细时，主动进入下面的循环，不只丢给用户一份字段清单，也不直接自行补齐后生图：

1. **归纳已有信息**：先读对话、文件和参考图，只列与当前阶段相关的已知项、拟定项和缺口。用户刚给的答案不再重问。
2. **问当前最关键的 1–3 项**：优先解决会明显改变“是谁、长什么样、怎样生活”的问题。问题用普通语言，合适时给少量清楚的方向；允许自由回答，不要求用户理解 Schema 或摄影参数。
3. **等待并整合回答**：关键问题没有答案时不视为同意，不因等待时间经过就自行代填。用户只答了一部分就保留已答部分，再问仍影响下一步的缺口；可以继续整理不依赖该答案的资料。
4. **更新可修改的草案**：简短反馈已经明确的核心设定和仍待决定的项目。用户改变主意时采用最新选择，说明会影响哪些外观或参考，不恢复其已删除的设定。
5. **检查推进条件**：信息足够就进入下一阶段；不足则继续下一轮。不要把姓名、精确生日、三围、每周课表或完整人生故事设为所有人物都必须填完的门槛。

例如只有一句“想做一个喜欢画画的人物”，第一轮可先问人物年龄段／生活身份、希望的外观气质、是否已有身份参考；下一轮再根据答案补常住位置、性格与互动偏好。已经给了清楚身份照的人物，不再机械追问照片能直接描述的每个五官细节，但不从脸推断职业或住处。

用户说“不知道”时给具体可修改的建议；说“你帮我定”时，在其授权范围内代拟并清楚展示，不能把未授权的其他关键事项也当作已确认。用户已经授权按草案直接生图时，信息达到相应条件就继续，不再重复询问是否同意。

## 什么时候可以进入下一步

| 下一步 | 必须具备的信息 | 仍可保留的待定项 |
|---|---|---|
| 生成人物主参考候选 | 新人物／延续既有人物的方向清楚；年龄或年龄表现有依据；核心外观及面部结构、头肩比例已选定或明确授权代拟；已有参考的用途与保留特征明确；生成及保存位置可用，且本次已要求创建参考图 | 没有指定的精确生日、完整经历、详细生活日程；尚不影响中性身份图的生活设定 |
| 把候选设为正式主身份图 | 用户已经选定具体图片；实际图片可用，主要身份冲突已解决，版本与来源可记录 | 不影响识别的生活细节；不能把未选定候选设为 ready |
| 首次持续性日常拍摄 | 有可用且选定的主身份图；生活身份与性格足够决定动作；有可用的默认生活位置或本次明确地点；摄影／互动偏好已给或用户接受默认选择；可按规则取得时间和天气；本次请求包含日常照片 | 可在以后补充的兴趣细节、关系和经历；未定义事项不得在画面或贴文里冒充既有事实 |
| 已有人物的其他类型创作 | 有可用且选定的身份参考；已读取本次类型模块；完成其关键输入，例如完整封面的刊名／标题和版式用途；本次已请求该交付物 | 不影响本次类型的生活信息；明确棚拍封面不要求先补人物当前城市天气 |

默认风格可以选择 natural_daily，但资料不足且用户尚未选定主要创作方向时，应先解释建议再问关键问题。城市缺失时可以先完成已授权的中性身份候选设计；在默认日常拍摄前仍须补齐人物位置，不能用电脑所在地替代。

在人物草案目录的 setup.md 简记当前阶段、已答项目、关键缺口和下一轮问题，并同步 profile 的 proposed／unknowns。下次从未完成处继续；记录本身不代表用户已经确认，也不要为问答进度修改已发布的 Canon 版本。

## 没有参考图时，一起建立主身份图

用户要求创建角色和参考图时，使用可用的生图工具完成首次设计。首张不伪称有身份参考；prompt 明确它是新人物设计。仅要求改 Skill、人设或提示词时不调用生图。

未指定候选数量时先生成 1 张主身份候选，先前提出的多个文字方向不自动转换成多个付费生成请求。用户明确要求多个视觉候选时按指定数量执行。根据 save_records 决定是否写 JSON；当前任务状态必须真实，超时查询原任务，不重复提交。

主身份候选必须按 [identity-reference 正面定妆模板](../types/identity-reference.md) 编译：3:4 头肩近景、完全正面、双肩朝前自然水平、眼平直视，85mm 等效视角与中性柔光。人物段明确五官骨相、可见肩颈结构、肤色、发型及辨识点；机位与灯光模板不随人物更换。不要用侧脸、转肩、歪头或复杂生活情境替代主图；日常互动风格留给后续照片。启用记录时 JSON 使用 identity-reference 类型并保存模板依据。

这是专门的形象设计情境，可以明确使用创作的中性室内光线并标 scenario；不是跳过日常拍摄默认天气查询的通用例外。常住地仍需在日常场景开始前确定。

实际看图，逐项检查正面朝向、眼平视线、骨相与辨识点，再对照草案指出表现与偏差，展示候选，请用户选择“用这张”或给出修改点。第一张未经用户选定的图保持候选，不自动提升为长期 Canon。修改时保留旧候选和已存在的生成记录；接受清楚的自然语言选择，无须固定口令。

用户选定主身份图后，如日常拍摄确实需要更多角度或全身比例，再以选定主图为身份依据补充对应参考。全身比例参考采用正面全身模板；头肩主图不代表身体比例已经核实。先说明用途和数量并在已有授权范围内执行，不默认额外生成整套转面图、体型图和场景图。不一致的补充图不能混入有效身份参考。

## 建档、检验、继续

用户选定的主参考存入人物目录，生成记录仅在用户开启时保存；为 profile 分配稳定 ID 和正式版本，记录 primary_identity、图片 SHA-256、canon_version、active 和来源。只有文件可用、主要身份冲突已解决、主参考已选定才设为 ready；其他缺口明确保留。

建议资料库保留：

```text
characters/<profile-id>/
  profile.json
  references/                 选定身份图与必要辅助参考
  candidates/<design-id>/     未选定或旧候选；JSON 生成记录可选
  versions/<version>/        更换 Canon 时保留旧档案与其参考
<profile-id>/<shoot-id>/     日常图片与贴文；单份 JSON 及其引用快照可选
```

不要在哈希固定后覆盖选定参考或旧版本。把新人物登记到资料库 `index.json` 的 characters 列表，使用相对路径，让其他会话能发现并加载；保存位置配置留在项目配置或本机映射，不塞进人物 Canon。

交付时展示选定主图、简短设定摘要、人物档案和实际保存位置。若用户原请求还包括日常照片或其他类型创作，身份选择完成后按对应模块继续完成该请求，不再问是否继续；若只要求初始化，到完整建档为止。没有完成选择时明确哪些是草案或候选，保存进度便于下次接续。

## 行为核对示例

| 用户情况 | 应有行为 |
|---|---|
| “第一次用，想创建一位爱散步的中年插画师” | 补齐关键外观、生活位置和保存目录，给短草案，共同建立主图，不加载 Ari |
| “这是她的照片，帮我继续日常摄影” | 查看照片，询问缺失生活设定，使用用户选定的身份，不另造一张脸 |
| “已有 profile.json，给她三张胶片日常” | 验证档案与参考，读默认地点和当前天气，直接执行已授权的三张 |
| “参考丢了，但是上次那张脸别变” | 定位旧资料库；仍缺失则说明无法保证完全一致，一起恢复参考，不假称只凭文字锁脸 |
| “只完善初始化流程” | 修改技能与说明，不实际创建人物或调用生图 |
| “只给了模糊想法，其他还没想好” | 按关键缺口分轮问答；提供可修改的建议，信息不足时不直接生成并标为完成 |
| “这一轮只回答了其中一个问题” | 保存该答案，只追问仍影响下一步的缺口，不重启整张问卷 |
| “外观和性格你帮我定，城市用我指定的” | 在授权范围内代拟，保留指定城市，不扩展成自动代定其他身份事实 |

完成首次建档时，简短提醒用户可以要单张，也可以指定 3 张、6 张等连续系列套图。例如“给这个人物拍 3 张周末散步的系列照片，包含环境、行动和回应镜头的瞬间”。提醒只介绍能力，不自动增加已授权的数量；用户已要求套图时按原要求继续，不重复询问。
