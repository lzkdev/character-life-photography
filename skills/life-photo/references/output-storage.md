# 保存位置与归档

保存位置是执行配置，不属于人物 Canon。更换设备或输出盘不能因此改变人物档案版本与指纹。

## 是否保存拍摄记录

拍摄记录只选 JSON，默认关闭。初始化确定资料库位置时，顺带询问“只保存图片和贴文，还是也保留 JSON 拍摄记录”；已有明确选择直接使用，未选时采用 `save_records: false`，不把这项可选偏好变成生图阻塞。用户说“只要照片”时进一步省略贴文。

优先级：本次明确要求 > 项目配置 `.character-life-photography.json` 的 `save_records` > 默认 false。“以后都保存／不要记录”才更新长期设置；临时要一份 JSON 只影响本次。

- false：保存实际图片和范围内的一份 caption.md；不自动输出逐图 JSON、MD 阅读副本、计划、prompt.txt、weather.json、shoot.json、类型快照或验证报告。
- true：每张保存一个 `<shot-id>.json`，包含身份引用、方案、完整提示词、天气依据、真实执行结果与 QC。提示词和天气已在 JSON 中，不再分拆为重复文件；不生成对应 MD。需要离线可迁移的详细记录时保存该 JSON 引用的参考、档案及类型快照。

关闭拍摄记录仍须查看参考、查询适用天气、检查成图、核实实际保存，并保留当前在途任务状态避免重复提交；这些工作不要求生成额外交付文件。需要临时校验文件时只用于本次工作，不进入用户作品目录或分享包。

人物 profile.json、选定主参考和简短初始化进度用于长期人物管理，不是每张照片重复生成的拍摄记录。它们每个人物维护一份及必要历史版本；不因关闭拍摄记录删除或重建。资料库索引只保留发现人物与作品所需的简短条目，不追加同内容的 MD 目录副本。

## 解析目录

按以下顺序使用首个适用项：

1. 用户本次明确指定的输出根目录；仅对本次生效，除非用户要求设为默认。
2. 当前实际项目根目录的 `.character-life-photography.json`。
3. 本 Skill 的 `settings.local.json` 中与本次 `profile_id` 匹配的项目映射，再读取该项目的配置。
4. 已明确关联、由用户管理的普通项目目录下 `photography/`。会话自动生成目录、临时工作树和工具图片缓存不属于这个默认项。

没有适用目录时先询问一次长期资料库位置，可以同时准备拍摄方案。已配置的目标不可用不算“未配置”，不要越过它静默使用后备位置。已知人物映射对应的共享盘若未挂载，也应先报告，避免误用当前无关项目。

共享资料库可容纳多个人物，按 [多人物选择](character-selection.md) 登记并隔离档案、候选与作品。新人物沿用用户选定的资料库根目录时建立独立人物目录，不复制其他角色的 Canon。

项目配置示例，`output_root` 为绝对路径或相对此配置文件所在项目根目录的路径：

```json
{
  "version": 1,
  "output_root": "photography",
  "profile_root": "photography/characters",
  "save_records": false
}
```

本机映射示例：

```json
{
  "version": 1,
  "profiles": {
    "character-id": {
      "project_root": "/absolute/path/to/character-project"
    }
  }
}
```

本机映射只适用于这台设备，不打入可移植 Skill 包。另一台设备应使用它实际打开的项目根目录，或重新填写该设备的映射；不能假定不同设备的本地目录和共享盘挂载路径相同。

profile_root 同样相对项目根目录，省略时用 `<output_root>/characters`。共享盘的本机映射另加 required_mount，值为真实挂载点；普通本地文件夹不填此项。可移植包只带配置示例，不带开发者自己的默认目录或人物映射。

## 写入前后

- 存在 `required_mount` 时，用文件系统挂载检查确认该目录当前是挂载点，再检查实际项目存在；不能自行创建缺失的共享盘根目录。在本次新目录中验证能写入并删除自己创建的探针文件，再调用生图。
- 每组使用 `<output_root>/<profile_id>/<shoot_id>/`；shoot_id 包含日期与简短情境，同名冲突时增加唯一后缀。只在明确接续同一组时重用目录，修改或重生成使用新文件名。
- 按上面的开关保存图片及可选单份 JSON。不开记录时不为每次拍摄复制整个人物目录。详细记录中的快照服务于引用与迁移，不产生 JSON 的 MD 镜像。
- 图片必须是实际文件副本，不能仅保存临时 URL、指向会话缓存的符号链接或聊天附件标识。先保留工具返回的原图；复制后比较 SHA-256，启用记录时再验证新位置的 JSON 引用。
- 启用记录时，图片及档案引用使用明确的相对基准；贴文按实际图片顺序组织。生成图片用 `generation.image.path_base = "record"` 和相对 metadata 文件的 `local_path`，让整组在另一台设备仍可读取。省略 path_base 的旧记录继续按绝对路径解释。
- 本地归档的 Markdown 图册可用相对路径；在聊天里展示本地图片时仍使用真实绝对路径。
- 迁移旧组时复制到新目录，只改副本内的文件位置引用，保留原图、原档案、原提示词的字节。记录迁移来源和校验结果，不重跑生图、不把归档时间冒充生成时间。
- 资料库只维护一份简短 `index.json`，增加新组时保留旧条目，不默认再生成目录页。资料库中的完整副本和目录入口应不依赖原会话；只有校验通过才标记已归档。普通文件夹不等于额外备份，也不承诺平台删除会话的具体清理行为。
