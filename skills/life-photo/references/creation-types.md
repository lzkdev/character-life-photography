# 创作类型与独立扩展

本 Skill 自带初始化、人物与参考管理、镜头互动、记录和归档规则。使用某个人物、模型、共享目录或其他 Skill 不是安装前提；实际生图仍需当前环境可用的图像生成工具。各创作类型统一通过 life-photo 调用。

## 选择本次类型

| type_id | 请求识别 | 读取的模块 |
|---|---|---|
| identity-reference | 初始化正面定妆、补建主参考或身体比例参考 | [正面定妆模板](../types/identity-reference.md) |
| daily-photo | 日常照片、街拍、手机随拍、生活写真；未另指用途时的默认类型 | [日常摄影](../types/daily-photo.md) |
| magazine-cover | 杂志封面、带刊名标题的封面设计、封面人物底图 | [杂志封面](../types/magazine-cover.md) |

类型决定交付物和必需信息，摄影风格决定视觉质感，interaction 决定镜头关系。这三者独立：例如“杂志封面＋胶片风格＋有互动感”是一个可用组合，不需要复制整份 Skill。只加载本次选中的模块。初始化定妆采用 identity-reference 固定机位；它不覆盖日常或封面风格。请求仅比较或完善类型时不生图。

未登记的新类型可以先明确需求并准备类型说明；不能声称已经加载不存在的模块或完成了该类型的验证。

明确说做封面时选择 magazine-cover；只说照片有杂志感时，不自动加刊名和文案。用户目标仍不明且影响交付物时只询问这一关键区别，同时准备不依赖答案的部分。

## 共用与专用内容

- 核心负责人物身份、分轮问答、参考与来源、执行状态、检查、文件位置、可选的单份 JSON 记录和交付。切换类型不复制或重写人物 Canon。
- 类型模块负责额外输入、情境与天气是否相关、构图或版式、类型专用参数、最终文件及检查项。日常的当前天气规则保留在日常模块；棚拍封面可以使用明确设计的灯光。
- 人物档案与照片保存在用户资料库；本机目录映射留在 settings.local.json。可移植包不夹带人物私有材料、账号或路径，不依赖发布流程。
- 不把类型扩展写成必须安装另一套 Skill 的链条。只有当前任务确实需要、且环境可用时才使用其他工具或能力。

## 类型记录契约

开启 JSON 记录时，计划与结果在同一个记录里保存 creation：

```json
{
  "type_id": "daily-photo",
  "type_version": "1.0",
  "spec": {}
}
```

type_id 是类型标识；type_version 是本次实际使用的模块版本；spec 只放此类型的参数，不复制人物外观、天气查询结果或生成状态。共同字段继续按 image-record.schema.json；已提供专用 Schema 的类型，另用该 Schema 验证 spec。只验证共同字段不能声称类型参数也通过了校验。

旧记录缺 creation 时按原有日常记录读取，保留原文件与版本；不要虚构它当时使用了哪个新增模块版本。启用详细记录时保留选用模块的 MD 快照，便于以后核对创作依据。

## 新增类型

新增 types/<type-id>.md，并在上表登记入口；如需稳定的结构化参数，再增加同名 .schema.json。模块说明包含：类型 ID／版本、适用请求、必需信息与问答、场景和天气规则、构图或版式、spec 字段、交付物、实际检查项。核心流程与人物档案不随每个新类型重写。

模块里的建议不能自动变成人物不变量，也不能取消核心的真实执行状态、选定身份参考和实际成图检查；是否保存这些拍摄资料服从 save_records 设置。需要新的共同字段时才演进公共 Schema，不能把所有类型的字段都加成全体记录的必填项。

新类型以一份明确未生图的计划验证输入与记录；实际生成后才评价视觉效果。功能模块已经写入不等于完成了该类型的生图实测。
