# 杂志封面

type_id: magazine-cover  
type_version: 1.0

在共用人物档案、身份参考、存储和生成记录的基础上组织封面人物与版式。读取本模块不自动创建图片，执行范围以本次请求为准。

## 先区分交付物

- **cover-image**：只生成适合做封面的无字人物图，给刊名与标题留出空间。用户只要封面感写真或无字底图时，不擅自添加文字。
- **finished-cover**：包含人物图与刊名、标题等完整封面。只说“做杂志封面”时按完整封面理解，先补齐必要文字；未给刊名不能自行伪造真实出版方。

没有指定数量时默认一个方案、一张最终封面。多种候选或分步生成的额外图片在执行前说明用途与数量，在已有授权范围内进行；不因类型新增而静默多次付费生成。

## 分轮补充封面信息

沿用已有人物档案。每轮只问 1–3 个当前缺口：

1. 是完整封面还是无字底图；主题／阅读对象及希望的视觉气质。
2. 完整封面的刊名、主标题、需要的副标题、文字语言。用户让你代拟时先给可修改文案，不冒充真实采访、真实刊期或已出版内容。
3. 棚拍还是外景、比例与交付用途；已有版式或参考时先读取。只做数字预览而未指定比例可采用 2:3 竖幅并说明，不假称印刷尺寸。

不是所有封面都需要副标题、日期、条码、价格或徽标；只保留用户指定或已选定的内容。用户要求可印刷文件时先取得实际尺寸、出血及印厂要求，不能用像素尺寸证明印刷交付已经达标。

## 摄影与文字协同

- 棚拍可以采用明确设计的背景和布光，context.weather 标 scenario 并说明；不用人物当前城市的天气强加到摄影棚。外景封面采用人物默认位置和当前环境时，按 [日常模块](daily-photo.md) 查询当地时间、天气；用户指定的历史或创作情境优先并保留来源区别。
- 沿用用户选择的摄影风格和镜头互动；没有要求互动时不自动让封面人物探身，也不自动改变脸、年龄、身材或皮肤。
- 先安排人物位置、脸部保护区、刊名与标题的阅读顺序和留白，再组织构图。默认让眼睛、鼻子和嘴保持清楚；用户要求文字遮叠时按明确设计处理。
- 封面文字作为独立内容逐字记录，再写入生成或排版要求。使用符合当前工具规范的方法完成；只有实际交付可编辑文件时才称为可编辑版。纯图片工具的结果只称图片。
- 若文字或构图未通过，指出具体错误并处理；不能交付无字底图却宣称完整封面已完成。

## 类型参数与文件

creation.spec 按 [封面参数 Schema](magazine-cover.schema.json) 保存 deliverable、setting、aspect_ratio、copy 和 layout。print_requirements 只在用户提出印刷要求且已提供信息时填写。人物、实际图像尺寸、工具返回值、天气依据和检查结果仍使用共同字段。

默认保存实际封面图片与范围内的一份贴文；开启记录时才将计划、提示词与结果合入每图一份 JSON，不生成对应 MD。完整封面的文字在生成前核定；用户需要文字文件时只保存一份 cover-copy.md，不再另存相同内容的 cover-copy.json；封面文字与 caption 贴文分开，沿用用户对配套贴文的范围要求。多阶段产生的底图和最终封面分别命名并记录关系，不能覆盖旧结果或混淆哪个是最终文件。

## 查看实际结果

核对人物身份与要求的摄影／互动，再检查：刊名和全部标题逐字准确；阅读层级和对比清楚；文字未出界，人物脸部可辨；比例与用途符合；没有未经要求添加的条码、刊期、价格或出版声明。看图确认字体和文字，不把 prompt 正确等同于图上的文字正确。
