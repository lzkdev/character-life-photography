# 人物摄影与视觉创作

让同一个人物在不同日常情境、不同摄影风格里继续生活。以人物档案锁定身份，用本次拍摄方案控制变化，用真实成图检查发现漂移。默认交付图片与配套文字；提示词或 JSON 拍摄记录按需输出。共同核心与具体创作类型分开维护，保留原调用名。

## 独立核心与创作类型

人物档案、用户资料库和本机路径独立于技能逻辑。所需的初始化、参考管理、互动、记录与类型模块都随本包提供；不要求安装旧抓拍 Skill 或连接发布工具。按 [创作类型与扩展契约](references/creation-types.md) 选择本次类型，扩展类型时保留共用核心。

## 首次使用与入口判断

先识别本次任务是“完善 Skill”“初始化人物”还是“为已有人物创作图片”。只修改 Skill 时不创建用户未要求的人物，也不调用生图。按 [多人物选择与隔离](references/character-selection.md) 匹配人物：明确的新人物进入初始化；明确指定但未找到的名字先定位或确认新建，不能套用当前唯一人物。

- 已有可用人物档案和选定身份图：加载并核对后直接进入本次类型的创作，不重复初始化。
- 已有参考图但缺档案：按 [首次初始化](references/initialization.md) 查看图片，与用户补齐身份和生活设定；不从长相臆测职业、性格或居住地。
- 只有文字设定或完全从零：按 [首次初始化](references/initialization.md) 与用户一起拟定人设、生成身份候选图、选定主参考，再建立可长期使用的档案。
- 档案存在但参考缺失或未选定：从缺失步骤继续，保持 draft，不声称身份已经锁定，也不擅自用另一张脸替代。

初始化也确定资料库与默认保存位置；用户不用预先手写 JSON。包内示例用于说明结构，新用户没有选择时不自动加载为自己的人物。

新人物定妆采用 [固定正面定妆模板](types/identity-reference.md)：正面头肩、眼平机位、逐项骨相与自然骨架描述。拍摄模板固定，人物特征来自各自问答与参考；不为统一模板重画已选定的旧人物主图。

资料不足时，初始化必须进入分轮问答：读取已有答案 → 找出影响下一步的关键缺口 → 每轮问 1–3 项 → 等回答并更新草案 → 再判断是否足够。按 [首次初始化的推进条件](references/initialization.md#什么时候可以进入下一步) 决定何时生成参考或日常图；不能把关键设定静默补成已确认事实，也不为可选细节无限追问。

## 输入与输出

- 接受人物档案／参考图、日常活动、地点、摄影风格、数量与补充要求；资料足够时直接组织拍摄，不为普通创意选择反复提问。
- “互动感／陪伴感／像在和我说话”用于生图语境时，指人物与镜头所代表的画外同伴产生可见回应。按 [镜头互动](references/camera-interaction.md) 组织视角、触发、动作和目光；不要改写成社交贴文互动。
- 日常和使用当前环境的外景拍摄，未指定地点、日期或天气时自动读取人物预设位置、当地当前时间与天气。棚拍、封面版式等按类型模块确定环境依据。
- 每张提示词独立完整，包含人物、衣服、动作、机位、环境、光线与质感；多图不写“同上”。用户要图片时生成图片，要提示词时只交提示词。
- 普通日常单张请求默认 1 张，未给张数的“一组”按 3 张并说明；明确 n 张就按 n 张设计。其他类型采用各自的数量和交付规则。不要用长篇分析替代用户需要的成图或完整 prompt。
- 默认每组图片附一条配套贴文，基于实际成图和人物语气写作；用户明确只要照片、提示词或 JSON 时按其缩小的范围交付。

## 分开组织输入

1. **人物档案**：是谁、外观不变量、可变化项、生活背景、参考图及其版本。先读 [档案与连续性](references/profile-and-continuity.md)，按 [档案 Schema](references/character-profile.schema.json) 加载或建立档案。
2. **本次创作类型与内容**：按类型模块确定图片、封面或其他交付物；日常场景包含何时何地、在做什么、动作动机、天气、服装和道具；与镜头后同伴的互动关系、同组图片的延续关系。
3. **摄影风格**：选择 [摄影风格与场景](references/photography-styles.md) 中的预设，或使用用户给的摄影描述／参考图。风格改变摄影表达，不暗中改变人物的脸、年龄、族裔、肤色或体型。

需要抓拍感、观察式构图或多图变化时，读 [机位、动作与提示词写法](references/composition-and-prompts.md)。它吸收原「角色抓拍摄影」的机位库与完整 prompt 写法，按本次风格选择使用。

用户已有档案时直接接入。未指明人物且当前上下文唯一明确时可沿用；有多个且指代不明时只确认人物。新人物建立独立 ID、候选、档案和参考，不继承其他人物的外观、生活位置或生成图片。用户让你定义新角色时可提出完整档案；自行补充的设定明确为 proposed，不伪装成既有事实。精确延续既有脸部却没有可用参考时先指出缺失，仍可准备情境与提示词；不声称文字已锁定身份。

用户人物档案从所选项目或指定路径读取。[示例档案](profiles/example-adult/profile.json) 是尚无身份图的虚构草案，只说明结构，不是已经确认的长期人物。

## 工作流程

### 0. 确定长期保存位置

先按 [保存位置与归档](references/output-storage.md) 解析本次指定目录、项目配置或本机人物映射，并确认目标可写。每组使用独立目录。按保存设置决定是否写拍摄记录：默认只保存图片与一份配套贴文；save_records=true 时每张另存一份 JSON，不自动生成对应 MD、独立提示词文件或整套重复报告。人物档案与主参考作为长期身份资料独立维护。未明确选择长期目录时，不把会话附件、临时目录或 Codex 管理的任务目录默认为资料库。

工具先把图片写到生成目录时，完成后复制到确定的资料库并验证文件，再交付资料库中的结果。共享盘不可用时先说明保存受阻，不能静默改存别处并宣称归档成功。

### 1. 锁定此次使用的人物版本

固定 profile ID、版本和文件 SHA-256；实际查看选用的身份参考。首次设计尚无身份图时走初始化分支；正式延续已有身份时，正面／三分之二侧脸用于脸部，全身图用于比例，环境图用于地点；根据画面选少量相关参考，记录每张用途。不同人物、不同发型时期或旧版本不混用为同等身份依据。

身份以用户明确指定的版本与参考为准；文本和图片存在关键冲突时先定位冲突。能按已有优先级解决的直接处理，影响“画的是谁”的未决冲突才需要澄清。

### 2. 按创作类型补齐本次方案

先按 [创作类型](references/creation-types.md) 选择并读取一个模块。日常照片默认 daily-photo；明确的杂志封面请求使用 magazine-cover；初始化定妆采用 identity-reference。资料不足时沿用分轮问答，只补影响本次类型的关键缺口。创作类型决定场景、版式和交付物；人物身份继续由同一档案与选定参考维护。

日常及采用当前环境的外景仍读取人物预设位置、当地当前时间并查询天气；专门的棚拍或版式创作按所选模块记录明确的设计情境，不伪装成当地实况。新的事件、造型与文字标为 proposed，用户提供内容和来源事实分别保留。

启用记录时，新 JSON 写入 creation.type_id、type_version 和 spec；需要完整可迁移记录时一并保存引用的参考与类型快照。未启用时只在本次工作中核对这些信息。摄影风格和镜头互动分别选择，不为更换类型重写人物 Canon。

### 3. 匹配摄影风格和画面变量

用户本次指令优先，其次人物档案里的风格偏好，最后默认 natural_daily。手机与纪实不强加长焦浅景深；夜景不强加高键阳光；胶片感不抹去人物原本的肤色。根据事件决定机位、景别、光源、色彩、人物目光和动作阶段。

同一生活事件内保持衣服、道具、天气、空间与妆发连续；多图用环境、行动、反应等互补瞬间推进，不只是换姿势。风格可以跨组变化；同组切换风格时仍保持物理事实。不同风格参考中的人脸不替换身份参考。

### 4. 编译并生成

启用拍摄记录时按 [记录契约](references/image-record.md) 和 [Schema](references/image-record.schema.json) 保存每图一份 JSON；关闭时直接组织提示词和本次工作状态，不为执行流程强制创建用户未要求的资料文件。组合为：一次身份块＋本次类型与内容＋需要的镜头互动＋摄影风格＋类型专用构图或文字要求＋必要的一致性约束。检查正负提示词是否冲突。若已验证的执行器会注入身份，只给它 scene prompt，避免重复强化体型与肤色。

只要方案／提示词／技能时不调用生图；要求出图时执行已授权的数量与提供方。已有可用生成入口时继续执行，不只停在交提示词。

使用当前可用且支持所需参考图的工具，遵从该工具及相关生图技能的实际调用要求。不要把某个模型、seed、比例或旧脚本写成人物不变量。记录真实返回的模型、任务、图片和尺寸，未知填 null。

处理中查询原任务；超时先查在途记录，不重复付费提交、不静默换模型。切换模型或主要参考后，先检查一张已授权的成图再扩大同批执行。没有执行能力时交付完整方案并说明缺口，不假称已生图。

### 5. 看成图，保存延续依据

查看实际图片，并对照本次固定的身份参考检查：

- **身份**：脸型与五官关系、辨识标记及左右、发色与长度、年龄感、体型、固定饰品；光照变化不等于身份变化。
- **生活**：动作有动机，手与物品的接触自然；衣着、天气、光源与空间合理；同组前后没有无解释的变化。
- **互动**：要求回应式互动时，能从目光、转向、动作中断或递示物品看出她／他在回应镜头后的同伴；不能只有文字声称“互动”。同伴不入镜也能成立，不为证明互动多生成人物或手臂。
- **摄影**：选用的风格确实表现出来，人物与必要环境可辨；不像只给同一张照片换滤镜。
- **类型与完成度**：完成选中类型的实际检查项；人体、文字、数量与尺寸符合要求；没有意外多出的人或镜像。用户要求合照或反射时按该构图检查，不套用永久“只准一人／禁止镜子”。

未看图保持 not_reviewed；发现漂移标 needs_revision 并说明具体偏差。通过检查的日常图也不会自动晋升为新身份母图。修正图用新文件名，保留旧记录；更新人物 Canon 时建立新版本，历史图片继续指向原版本。

## 交付

展示实际图片，简短说明数量、保存位置和仍需修正的问题。仅在启用记录或用户明确索取时提供每张 JSON；不生成配套 MD 阅读记录。用户只要方案时直接给完整提示词，不默认附 JSON。内部状态检查照常完成，未启用记录时不另造报告文件。

交付时说明实际保存目录；资料库的单份简短索引保留作品位置；启用记录时使用可解析的相对文件引用。目录未确认写入并核验前，不报告“已长期保存”。

看过成图后，按 [配套贴文](references/caption-output.md) 为整组写一条可直接复制的贴文，只保存一份 caption.md，不再额外生成同内容的 caption.json；封面内文字等类型专用内容独立保存，不混入贴文。贴文只做内容输出，不触发账号、消息、排期或发布操作。

人物稳定性需要参考图、执行入口和成图核对共同维护；不得把“同 seed”“提示词未变”或文字检查通过当成成图身份一致的证明。
