# 多人物选择与独立初始化

一个资料库可以管理多个人物。每次先确定人物，再加载档案和参考；人物 ID、版本与参考的绑定沿用共同记录契约。

## 先匹配，后创作

1. 用户指定 profile 路径或 ID 时以它为准。否则读取资料库 `index.json` 的 `characters`，按 ID、显示名称或用户确认的别名匹配，加载档案核实；目录页不是人物身份的最终来源。
2. 已匹配且 ready：验证该人物的主参考，进入本次拍摄。已匹配但 draft：读取该人物的 `setup.md`，从未完成的初始化步骤继续。
3. 明确说“新建一个人物”或“新人物叫……”：进入 [初始化问答](initialization.md)，为新人物分配独立目录。已有完整资料时跳过已解决问题；有用户选定的可用参考时不强制重新生图。
4. 明确给了一个找不到的名字：先查指定项目与已登记资料，仍未找到时简短确认是新人物还是已有档案在别处。不能因为资料库只有一位人物就把这个新名字映射过去。
5. 没说名字，但当前对话明确正在为某人物创作：沿用它。既无当前人物又有多个候选，或同名／别名命中多人时，询问用户选哪一个，保留各自资料。

角色名字不等于稳定 ID。新建时使用不含路径分隔符的独立目录名；同名冲突使用新 ID 并让用户区分显示名称，不覆盖同名目录。别名由用户确认，不能凭读音或长相把两人合并。不同资料库中的同名 ID 也不能自动视为同一人。

## 保存与发现

每个人物单独保存 `characters/<profile-id>/profile.json`、参考、`setup.md`、候选与版本；作品按 `<profile-id>/<shoot-id>/` 分开。一个资料库根目录可以共用，但人物的年龄、骨相、身形、位置、风格偏好、英文或其他语言贴文偏好分别读取。

`index.json` 保留已有的 `characters` 与 `shoots`。人物条目至少有 `id`、相对资料库的 `profile` 路径和 `status`；可增加 `display_name` 与 `aliases` 供选择。旧条目没有名称时从 profile.display_name 读取。新人物可先登记 draft，用户选定主图后只更新该条目的状态；不要重建索引丢掉其他人物。

示例登记结构，仅示意两个人物，不会自动创建他们：

```json
{
  "characters": [
    {"id": "character-a", "display_name": "人物甲", "aliases": [], "profile": "characters/character-a/profile.json", "status": "ready"},
    {"id": "character-b", "display_name": "人物乙", "aliases": [], "profile": "characters/character-b/profile.json", "status": "draft"}
  ]
}
```

切换人物时重选该人物的参考图和默认地点。另一人物的图只在用户明确指定其非身份用途时作为风格／场景参考，不与当前主脸混成一组身份输入。用逐图校验检查 profile ID、版本、参考角色与 hash；文字校验不能替代看图。

“给甲乙各拍一张”按两个人物各一张记录处理。只有用户要求同框才是合照；当前逐图核心为单一 character，不能用一个人的字段假装记录了两个人的身份。合照需另行明确多主体记录与参考绑定，不由多档案管理自动推导为已支持的合照模块。

## 常见入口

| 请求 | 处理 |
|---|---|
| “新人物叫 Lin，从零开始” | 建立 Lin 的独立草案，进入分轮问答与正面定妆流程 |
| “继续 Lin，上一轮只定了脸型” | 读取 Lin 的 draft 与 setup，补剩余信息 |
| “给 Ari 拍一张”且 Ari ready | 直接加载 Ari，不重复初始化 |
| “给 Ren 拍一张”但只找到 Ari | 定位 Ren 的资料或确认新建，不套用 Ari |
| “给她拍照”且没有明确当前人物 | 多人时询问选择，一人时可沿用唯一人物 |
